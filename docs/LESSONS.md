# Lessons

Mistakes already paid for. Read before working; append a row when you learn one (newest last).

| Date | Lesson | What happened |
|---|---|---|
| 2026-10-16 | Lint for `no-undef` after every carve | Porting the single file into ES modules surfaced `obsSpacing` referenced in an `if (false)` block; sloppy-mode inline scripts hid it. `npm run lint` now catches any identifier left behind when moving code between modules. |
| 2026-10-16 | Module bindings are read-only | Imported names (`GameState`, `InputState`, data tables) can be mutated property-by-property but never reassigned. Keep shared state as objects; never `GameState = {...}`. |
| 2026-10-16 | Base path everywhere | The app lives at `/outatime/`. A root-absolute URL works in `npm run dev` habits but 404s in production; use imports or `import.meta.env.BASE_URL`. |
| 2026-10-16 | Local e2e: use the headless shell, not full Chromium | `/opt/pw-browsers/chromium` is full Chrome. It requests `/favicon.ico` (we ship none), which 404s and trips the console-error guard, even on main. Point a throwaway config's `launchOptions.executablePath` at `/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` (what CI uses) and all e2e pass. |
| 2026-10-16 | **Auto-merge can stall on a CLEAN, green PR.** PR #5 sat with auto-merge armed, every check green and `mergeStateStatus: CLEAN` for 5+ min. If that happens, push an empty commit (re-triggers evaluation) or ask the operator; never merge red. |
| 2026-10-16 | **The IP denylist test also scans comments.** A code comment naming a trademarked arcade game failed CI. Describe genres generically (synthwave, arcade racer). |
| 2026-10-16 | **GitHub ignores `merge=union` when computing mergeability.** `.gitattributes` makes local rebases of CHANGELOG/LESSONS conflict-free, but a PR can still show DIRTY on GitHub after another PR lands — and CI's `check` won't even run on a DIRTY PR. If your PR goes DIRTY: `git fetch && git rebase origin/main && git push --force-with-lease`. |
| 2026-10-17 | Screenshot-driven grooming finds what file reading misses | Playing level 1 showed legacy real-place names (Wangan, Mulholland) and a coach card, two fork banners and two nameplates stacked on screen, none visible from reading `data.js` alone; tickets 0018/0019 came from that. Launch headless via `/opt/pw-browsers/chromium_headless_shell-1248/chrome-headless-shell-linux64/chrome-headless-shell`, click `#btnStartRace`. |
| 2026-10-17 | Never detect a *tap* by polling held-input state once per frame: a touch tap can press and release between two frames. Hook the input event itself. | The first-run steer prompt ignored quick taps on ◀/▶ on a real phone-sized run; only held presses cleared it (caught by a live Playwright play-through, now an e2e). |
| 2026-10-17 | **`body.on-title header { visibility: hidden }` hides every `<header>` on the page**, not just the HUD's. A new overlay's `<header>` vanished on the title; use a `div` with a class for overlay chrome. Also: Workers that implement Durable Objects get no PR preview URLs, so live-race changes are verified by `tests/e2e/live.spec.js` (wrangler dev) and on production after merge. | Live-room lobby showed no room code in e2e until the tag was changed (0060). |
| 2026-10-17 | **An inline `transform` beats a class `transform`.** Touch controls are positioned with inline `translate3d`, so a `.pressed { transform: scale(.9) }` silently did nothing (and a transform transition made an editor drop look mid-flight in e2e). Use the individual `scale` property for press feedback, and never transition the positioning transform. | Caught by the layout-editor e2e measuring a button 110 px from where it was dropped. |
| 2026-10-17 | **Don't release touches on window `blur`.** Parallel Playwright workers (and some real devices) blur the window while fingers are still down, which dropped the stick mid-drag. Pointers end with `pointercancel`/`lostpointercapture`; leaving the app hides the page (`visibilitychange`/`pagehide`). | Flaky multi-touch e2e under `--repeat-each=3`; stable 39/39 after the change. |
| 2026-10-17 | **Measure the bundle against origin/main, not your stash.** The touch kit first added ~15 kB gz to the entry chunk (58.8/60). Splitting it — controller loaded only on touch devices, panel/editor on first open, `save.js` importing a tiny settings module instead of the layout engine — brought the entry chunk back to ~49 kB. | `tests/e2e/budget.spec.js` would have failed the next feature. |
| 2026-10-17 | **`scale` + positioning `transform` = a button that jumps when pressed.** The individual `scale` property is applied *before* `transform` in the matrix, so it scaled the `translate3d` too and flung a pressed WARP ~100 px toward the top-left on a tablet. Position with the individual `translate` property when you also use `scale`. | Seen only on a production screenshot with fingers down; the e2e now asserts a pressed button stays centred. |
| 2026-10-17 | **Era art can be an IP reference by combination.** Reusing the courthouse clock-tower backdrop in a 1955 era turns a generic silhouette into the most recognisable film reference there is; new eras pick their own landmark (`backdrop.landmark`). Also: main JS is at ~59.7/60 kB gz after 0008 — the next content ticket must make something lazy first. | Caught by the Builder self-review subagent on PR #44 before merge. |
| 2026-10-17 | Backlog tickets go stale in halves | 0013 (analog touch + rebinding) was half shipped by 0061; check each acceptance line against `main`, then narrow the ticket instead of leaving it to be rebuilt. Also: `grep visibilitychange` before assuming a game pauses when hidden — only the touch kit listened. |
| 2026-10-17 | **Scene art lives in lazy chunks; the main bundle only gets a shim.** Moving the 2D backdrop out of main.js into `src/scenes/` (stage + one chunk per era) freed ~0.5 kB of main while adding six detailed worlds. Comments are scanned by the IP denylist too: "skyline" (a car model) and "flux capacitor" both failed it — say "roofline" and "warp". | 0100 |

Before blaming your diff, grep main's latest CI log for the same test and its `[perf]` numbers. | PR #67 (0019, fork cue) failed 3 CI attempts on mode3d/share/perf; locally all passed serially and frame cost matched main. | 2026-10-20 | **Patterns from a fixed pool can't be placed one recycled car at a time.** A car frees only when you pass one, so by the next free slot the pattern's head is inside the spawn horizon and the rest is dropped; park passed cars and place the whole pattern once enough are parked. Patterns that share the road must also share one speed, or the faster one catches the slower one up. | 0027: the self-review simulated the first version (WALL completed ~3%, CONVOY ~33%), then caught mixed-speed overlaps in the second; both unit tests now drive the real pool and speeds. |
| 2026-10-20 | Playwright workers re-read the config file while the suite runs: moving or deleting a local `-c` config mid-run fails every later test at 0 ms. Keep it in the repo and list it in `.git/info/exclude` instead. | 0027 local e2e: 37 "failures" that were just the moved config. |

When a lazy chunk already exists for the area, load *that* at boot (0013: `settings-ui` calls the existing `loadPanel()` when keys are rebound) instead of adding a second import; and optional `InputState` fields can stay unset (`?.`/falsy) instead of being declared in main. | 2026-10-22 | **Giving one grid column a `min-content` floor moves the squeeze onto its neighbours.** The phone HUD cards had `min-width: 0`, so once the race-time column held its width the position cards /6 and the WARP READY label spilled sideways out of their cards. A box-to-box overlap check cant see that, and `scrollWidth − clientWidth` misses overflow to the left. Assert that each card's text rects stay inside the card, and sweep 320/360/375 px with the widest place, label and score. | 0202: the self-review measured "/6" on top of the race time at 320x568; the cards now have `min-content` floors and phones under 375 px get slimmer numbers. |
| 2026-10-22 | **The touch kit re-lays itself out whenever `<header>` resizes, so a HUD whose height changes mid-race used to drop held fingers.** 0202 let the phone speed card wrap once the score grows (0 → 500 PTS took the header from 121 to 134 px at 390x844), and the ResizeObserver's `releaseAll()` let go of the thumbstick and slid buttons. Header resizes now wait until no finger is down; window resize and rotation still release. ResizeObserver watches the content box, so an e2e that grows the header must change its height (`min-height`), not its padding. | main red after #147: resume.spec "dragging the thumbstick" and touch.spec "Fortnite slide" failed both CI attempts; the PR's own CI never caught it because the first points landed at a different moment. |
| 2026-10-22 | **A live region that is `visibility: hidden` when its text lands is never read.** `body.on-title` hid `#announcerContainer`, and a race start removes the class and pushes the level banner in the same task, so screen readers skipped it; hide the region's children on the title, keep the region itself in the tree, and don't leave placeholder copy in it. An e2e that counts throttled writes must first wait for the line to go quiet: a real overtake at the launch opens the 2 s window before the test starts. | 0030: both caught by the self-review subagent before merge. |
| 2026-10-22 | **"Ready" for the warp is meter + cooldown, not the meter alone.** A boost inside the 12 s cooldown is a nitro purge, so a cue, label or hint keyed to `fluxCharge` alone promises a warp the button won't give (the touch button already did). The race step now publishes `GameState.warpReady` and every ready cue reads it; a test that pins `sinceWarp` must pin it past the cooldown. Also: a label swap inside a round button must be measured against the chord at its height, not the button's box. | 0112: caught by the self-review subagent on PR #151 (the first e2e pinned `sinceWarp = 0`, and "▲ READY" crossed the inner ring). |
| 2026-10-22 | **A danger cue must use the same rules as the hit it warns about.** The first proximity tick (0191) counted only traffic and obstacles, ignored height, and kept playing through warps, agro smashes, the finish roll-out and right after a crunch, so it would have ticked at 4/s exactly when you had already dodged by jumping or sliding, or could not be hurt. It now takes rivals too, checks the solver's own jump-over / slide-under / vertical-overlap rules, waits for `racePhase === 'RACING'` with no warp or agro, and skips a body you touched in the last 0.5 s. `?debug` never sounds it but counts `GameState.proxTicks`, so an e2e can watch it work. | 0191: all caught by the self-review subagent before the first push. |
| 2026-10-22 | **A shape metric that ignores edge direction calls a circle and a box the same.** The first colour-vision audit (0198) compared plain edge cells on a coarse grid, so a ring-framed coin and a square striped barrel overlapped at their tangents and the result flipped run to run at the threshold. Bin edges by direction (45° bins) before comparing, and measure the noise floor first: the same sprite at another distance (≤ 0.33 here) sets how high a "different" threshold must sit. Cut sprites out against two empty-road frames (pixels that differ between those are live detail) and keep only the biggest blob. | 0198: tuning ring thickness against the undirected metric went nowhere; the oriented one separated pickups from hazards by ~0.2 on every run. |
